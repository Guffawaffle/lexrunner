# AX (Agent Experience) contract

AX makes LexRunner operations predictable for both humans and agents. A machine-facing operation
needs bounded structured output, recoverable stable errors, and one semantic owner even when CLI
and MCP expose different transport shapes.

Full command-for-tool symmetry is not the goal. Interactive review, ideation, terminal navigation,
and local administration may remain human-only. `workflow.guide` is intentionally MCP-only. Where
parity is promised, both adapters call the same application service.

## Guarantees

### Bounded structured output

Canonical machine operations use one of the contract profiles recorded in
[`architecture/cli-mcp-surface.json`](architecture/cli-mcp-surface.json):

- `bounded-ax-v1` — bounded success data, stable operation/schema identity, artifact references
  for large output, and AXError failures with recovery actions;
- `agent-work-handler-v1` — bounded JSON-safe projections of durable Attempt lifecycle bodies; or
- `human-local-v1` — explicitly interactive/local output with no MCP parity promise.

Human formatting is a projection. It must not become a second implementation of plan, gate,
workspace, merge, or Attempt semantics.

### Recoverable errors

Machine failures carry a stable code, bounded message/context, and at least one next action. An
agent should be able to distinguish invalid input, authorization refusal, test failure, timeout,
external infrastructure failure, and inconclusive verification without parsing prose or logs.

### Semantic parity

Each approved CLI/MCP pair has one owning application service. Adapters validate and bound input,
call the owner, project the result, and map failures. They do not implement lifecycle transitions.

`WorkItem`, `Run`, and `Attempt` are ADR-010 coordination nouns. `IntegrationRun` is a deprecated
frozen integration-record noun and never orchestration authority. Plan/Gate/Weave remain owned by
the stateless integration core.

### Intentional parity exceptions

- MCP `workflow.guide`: agent-only workflow guidance; humans use CLI help and checked-in documentation
- CLI `lex-pr plan-review`: interactive human approval is intentionally not exposed as an MCP mutation
- CLI `lex-pr idea`: human ideation and GitHub issue creation remain an explicit local workflow
- CLI `lex-pr view`: terminal-interactive plan navigation has no machine-facing semantics

### Published deprecated MCP tools

- `lexrunner.getStatus` → status for integration; get_attempt_status for ADR-010 orchestration; remove in 2.0.0.
- `lexrunner.listArtifacts` → bounded artifact references from the owning plan.create, gates.run, or merge.apply operation; remove in 2.0.0.
- `lexrunner.startRun` → plan.create, gates.run, or merge.apply for integration; start_attempt for ADR-010 orchestration; remove in 2.0.0.
- `health` → doctor; remove in 2.0.0.

## Disposition meanings

- **Canonical:** supported vocabulary with a declared output contract.
- **Compatibility:** retained for a distinct existing caller with an explicit replacement.
- **Deprecated:** warns on use and carries a removal release.
- **Internal only:** developer/governance machinery, not a public parity promise.
- **Remove:** a live registration approved for deletion without replacement.

The complete per-registration classification—including CLI-only operations—is kept in the JSON
matrix instead of duplicated here.
