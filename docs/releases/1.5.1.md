# LexRunner 1.5.1 governed work and executable evidence recovery release

- Status: **release candidate**
- Prepared: **2026-08-23**
- Supersedes: **unpublished `lexrunner-v1.5.0` workflow attempt**

LexRunner 1.5.1 carries forward the full governed task/review, durable Attempt, disposable
workspace recovery, provider-terminal failure, and native Windows executable-receipt feature set
documented in the [1.5.0 release notes](1.5.0.md). The 1.5.0 signed tag remained immutable after
its workflow failed closed during ancestry verification, before dependency installation, package
publication, or GitHub release creation.

## Release correction

- Stable checkout still discards persisted GitHub credentials before executing repository code.
- Tag and commit signatures remain bound to the authorized release-owner primary fingerprint in an
  isolated GPG keyring.
- Main ancestry is now resolved through the authenticated GitHub compare API instead of a
  credential-dependent `git fetch` against the private repository.
- The stable job's `actions/checkout` and `actions/setup-node` revisions remain pinned to reviewed
  full commit SHAs.

## Compatibility and evidence

`lexrunner`, `lex-pr`, and `lexrunner-mcp` remain the published binary names. Node.js 24 or newer
and `@smartergpt/lex@^4.0.0` remain required. The complete 1.5.0 release evidence remains applicable
to its unchanged feature bytes; the 1.5.1 correction delta must additionally pass exact-head lint,
typecheck, build, all three full-test shards, Git-backed tests, Windows bootstrap, package and packed
consumer checks, performance smoke, publication dry-run, and independent general and hostile
review.

This remains a release-owner-signed, trusted-workflow npm publication boundary. Local shells and
agents may not perform non-dry-run publication. Only the signed-tag stable workflow may publish
through npm's package-scoped GitHub OIDC trusted publisher after every authority and package gate
passes.
