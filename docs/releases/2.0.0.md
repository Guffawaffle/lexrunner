# LexRunner 2.0.0 plan-bound gate evidence release

- Status: **release candidate**
- Prepared: **2026-08-29**
- Supersedes: **1.5.2**

LexRunner 2.0.0 makes local gate evidence explicitly plan-bound and exposes the same observation
through the CLI, SDK MCP, and published MCP server. This is a major release because its emitted
gate-receipt contract moves from schema v1 to v2 and declared container execution now fails closed.

## Breaking changes and migration

- Gate execution receipts use `lexrunner-gate-execution-receipt/v2`. Consumers that parse receipt
  files must accept the required `binding` object and validate its item, canonical-gate,
  candidate, and effective-timeout identities. The receipt's top-level `attempt` identifies the
  execution attempt, while `gate-evidence-manifest.json` separately binds the plan digest.
  Version-1-only parsers are not compatible with 2.0.0 receipts.
- A gate with a container declaration is rejected as unsupported. LexRunner no longer ignores that
  declaration and runs the command on the local host. Consumers must either use a supported local
  gate or wait for an explicitly implemented container executor.
- Gate artifact and flake-report path segments are derived from hashed item and gate identities.
  Consumers must use the paths reported by LexRunner rather than reconstructing legacy raw-name
  paths.

## Deferred compatibility removals

Deprecated CLI aliases, the MCP IntegrationRun adapters and `health` alias, `LEXRUNNER_*`
environment aliases, and legacy flat-path resolution remain available throughout 2.x so this
release does not combine the receipt migration with unrelated surface removals. Their coordinated
runtime metadata, warnings, tests, and documentation now schedule removal for 3.0.0. Consumers
should still migrate to the named canonical replacements during the 2.x line.

Plan Schema v1 and the package export map remain available. The published commands remain
`lexrunner`, `lex-pr`, and `lexrunner-mcp`. This release changes the gate-evidence artifact contract,
not the plan schema or command names.

## Evidence and authority boundary

- Receipt v2 records the item, canonical gate digest, Git candidate identity, top-level attempt,
  effective timeout, bounded output, timing, exit status, and artifact identities observed during
  retention. `gate-evidence-manifest.json` separately binds the receipt hashes to the exact plan
  digest and candidate. Together they form the evidence bundle inspected by status.
- Status rejects changed or stale candidates, duplicate identities, path escapes, and tampered
  manifests or receipts. It does not re-read retained gate artifacts after execution.
- Caller-provided receipt and manifest hashes remain observations with `authority: "unverified"`.
  They never enter `MergeEligibilityEvaluator` and cannot make an item merge-eligible. A trusted,
  plan-pinned verifier receipt remains separate follow-up work under issue #865.
- Gate timeouts have an explicit precedence contract: a per-gate `timeoutMs` overrides the
  hostility-adjusted operation default, and the effective value is recorded in results and
  evidence.

## Release verification

The candidate must pass lint, typecheck, build, the full hosted test matrix, Windows bootstrap,
Git-backed tests, package-boundary validation, packed ESM/CommonJS/CLI/MCP consumer smoke,
determinism, npm publication dry-run, and independent review against the exact candidate.

This remains a release-owner-signed, trusted-workflow npm publication boundary. Local shells and
agents may not run a non-dry-run publish; the signed-tag stable workflow publishes through npm's
package-scoped GitHub OIDC trusted publisher only after every release gate passes.
