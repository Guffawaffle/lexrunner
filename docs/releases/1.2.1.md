# LexRunner 1.2.1 publication repair

- Status: **release candidate**
- Prepared: **2026-07-21**
- Tracking issue: **#795**

LexRunner 1.2.1 is the npm publication candidate and adds a human-only publication gate for the
Ecosystem 3.1 work described in the
[1.2.0 release decision](./1.2.0.md). The 1.2.0 signed tag and GitHub release are immutable, but
1.2.0 was not published to npm after npm's publication normalization exposed a removable MCP bin.

## Repair

- `bin.lexrunner-mcp` uses npm's canonical `mcp-server.mjs` target, preserving the executable in
  the published manifest.
- `repository.url` uses npm's canonical `git+https` form.
- package validation rejects leading-`./` bin targets, missing shebangs, and repository URL drift.
- `npm run release:publish:check` validates the packed boundary, runs `npm publish --dry-run`,
  rejects npm normalization warnings, and prints but never executes the final publish command.

No CLI, MCP, schema, SDK, persistence, runtime, or dependency contract changed from 1.2.0. The
Node 24 floor and Lex 3 compatibility decision therefore remain as documented for that release.

## Publication boundary

After the signed `lexrunner-v1.2.1` tag workflow passes, an authenticated human runs the local gate
from a clean checkout of that tag. Only that human executes the command printed by the gate.
Agents and automation must not execute `npm publish` without `--dry-run` or respond to npm's
OTP/browser challenge on the release owner's behalf.

After npm accepts 1.2.1, issue #795 records registry metadata and native Windows Node 24 consumer
proof before the Ecosystem 3.1 release is considered complete.
