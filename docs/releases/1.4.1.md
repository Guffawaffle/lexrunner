# LexRunner 1.4.1 canonical CLI release

- Status: **release candidate**
- Prepared: **2026-08-04**
- Tracking issue: **#911**

LexRunner 1.4.1 corrects the package/executable mismatch exposed by a clean private-package
consumer install. Installing `@smartergpt/lexrunner` now creates a canonical `lexrunner` command
while retaining `lex-pr` as a compatibility alias to the same CLI entry point.

## User-visible changes

- The npm package exposes `lexrunner`, `lex-pr`, and `lexrunner-mcp` binaries.
- `lexrunner --version` and `lex-pr --version` execute the same 1.4.1 program and report the
  canonical LexRunner identity.
- Root help, generated shell completions, installation guidance, and current CLI/MCP surface
  guidance use `lexrunner` for new commands.
- Plain-text error, audit, and compatibility-warning prefixes identify the program as
  `[lexrunner]`, including in JSON mode where stdout remains machine-readable.
- Existing scripts that call `lex-pr` remain supported; this release does not remove or redirect
  any command implementation.

## Compatibility and install notice

- This is a patch release because it adds a missing executable alias and corrects user-facing
  identity without removing an existing package binary or command.
- Node.js 24 or newer remains required.
- The current native SQLite dependency can cause npm to print a deprecation warning for the
  transitive `prebuild-install@7.1.3` package. The warning originates in the latest available
  `better-sqlite3-multiple-ciphers` release, is not an npm audit vulnerability, and does not by
  itself indicate installation failure.

## Release evidence

The 1.4.1 release commit must pass lint, typecheck, build, the full test suite, both dependency
audits, install-script policy, package validation, packed ESM/CommonJS/CLI/MCP smoke, and
`npm run release:publish:check -- --allow-untagged`. The packed-consumer smoke must independently
resolve both `lexrunner` and `lex-pr`, compare their version output, and exercise the canonical
binary. The exact candidate must also receive the repository's independent review PASS before a
history-preserving merge to `main`.

A signed `lexrunner-v1.4.1` annotated tag may be created only after the signed release commit is
contained in `origin/main`. The stable workflow must then re-run the release gates and publish
through the package-scoped npm trusted publisher. Registry metadata and a clean native-Windows
private-package consumer smoke complete issue #911.

## Publication boundary

This remains a release-owner-signed, trusted-workflow npm publication boundary. Agents may
prepare, review, and merge the release candidate, but may not publish from a local shell. Only the
`stable-release` job in `.github/workflows/release.yml` receives GitHub OIDC authority after the
exact tag target, commit signature, signer fingerprint, manifest version, and `main` containment
are verified.
