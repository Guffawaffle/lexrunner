# LexRunner 1.2.0 release decision

- Status: **release candidate**
- Prepared: **2026-07-21**
- Tracking issue: **#795**

LexRunner 1.2.0 extends the deterministic merge-weave and fanout workflow into bounded assisted
agent work. It does not claim that the full proposed headless supervisor is production-ready.

## Compatibility inventory and semver

The next version is **1.2.0**.

| Surface         | Evidence from 1.1.0 to 1.2.0                                                                                                           | Decision                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| CLI             | Canonical plan/gate/weave and Attempt operations are additive; deprecated top-level aliases remain registered with 2.0 removal windows | Minor-compatible          |
| MCP             | 28 published tools are disposition-verified: 24 canonical and 4 deprecated; no published tool is removed                               | Minor-compatible          |
| Package exports | All nine 1.1 export keys remain; five schema targets now point at valid built artifacts instead of unpublished `.smartergpt` paths     | Compatible repair         |
| Schemas         | Agent-work, receipt, verification, authority, retry, and fan-in contracts are new and explicitly versioned                             | Additive                  |
| Persistence     | Coordination/workspace SQLite migrations create new fenced lifecycle state; the integration core does not consume it as hidden truth   | Additive, opt-in          |
| Runtime         | The engine floor moves from Node 20–22 to Node 24+                                                                                     | Intentional migration     |
| Dependency      | Lex moves from `^2.10.0` to `^3.0.1`; every imported export is retained and Node 24/package tests validate the line                    | Compatible after evidence |

The new capabilities warrant a minor release. The Node floor is a deliberate semi-breaking
Ecosystem 3.1 migration accepted for this minor release; it is called out in package metadata,
README, changelog, doctor output, and the migration guide. A 2.0 release remains reserved for
declared public-surface removals, including the deprecated CLI/MCP aliases.

The npm registry contained `@smartergpt/lexrunner@1.0.0` before this release. Repository tag
`v1.1.0` was not published, so 1.2.0 is intentionally the next npm version rather than attempting
to recreate or overwrite the old candidate.

## Supported progression

1. Freeze a deterministic PR/dependency plan.
2. Compute and apply authorized merge-weave operations through shared application services.
3. Retain bounded run, gate, receipt, verification, acceptance, and recovery evidence.
4. Harvest and analyze fanout evidence, including unsuccessful or unselected Attempts.
5. Prepare immutable task packets and execution envelopes for assisted workers, attach a
   foreground-owned worker session, ingest its claims, independently verify them, and apply policy
   acceptance.

Worker receipts remain claims. Engine verification owns accepted outcome truth. Git/GitHub writes,
merge, signing, secrets, release, and external-runtime access remain separately negotiated lanes.

## Maturity boundary

Supported in 1.2.0:

- assisted Attempt preparation, launch authorization, worker session, receipt, verification, and
  acceptance through shared CLI/MCP services;
- fenced memory/SQLite coordination and workspace stores;
- runtime-neutral adapter negotiation and explicit authority enforcement/declaration;
- fail-forward reconciliation planning and deterministic subprocess fixtures; and
- persisted merge-weave recovery and evidence-preserving fan-in.

Deferred from the supported release claim:

- a public unattended/headless worker-launch command or service;
- a supported autonomous operator across arbitrary agent runtimes;
- native host reboot/reconnect proof beyond the bounded consumer smoke; and
- the complete ADR-010 Stage 5 hostile fault-injection and authority-expansion matrix.

## Release evidence

The candidate must pass:

```bash
npm ci
npm run lint
npm run build
npm test
npm run test:git
npm run validate:package
npm run test:package
```

The packed smoke installs the real tarball into a clean consumer and verifies ESM, CommonJS,
public schemas, `lex-pr`, bounded read-only Attempt status without state creation,
`lexrunner-mcp`, and all 13 published Attempt lifecycle tools.

After npm publication, issue #795 additionally requires a native Windows Node 24 consumer to
install `@smartergpt/lexrunner@1.2.0`, verify the CLI, request MCP `tools/list`, and record package
integrity and cleanup without recording credentials.

## Publication boundary

The implementation PR prepares metadata and evidence only. Publication and signed `v1.2.0`
tagging occur from merged `main` as a separate explicitly authorized action. LexSona remains a
separate package and repository release; this release does not version or publish it.
