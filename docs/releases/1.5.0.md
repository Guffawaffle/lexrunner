# LexRunner 1.5.0 governed work and executable evidence release

- Status: **release candidate**
- Prepared: **2026-08-23**
- Source PRs: **#906, #926-#929, #931-#934**

LexRunner 1.5.0 packages the governed task/review foundation, durable Attempt awaitables,
disposable workspace recovery, provider-terminal failure handling, and native Windows executable
gate receipts developed since 1.4.1. It is a minor release because it adds public coordination and
review capabilities while preserving the existing CLI names, package exports, and plan-only
integration contract.

## User-visible changes

- Governed repository review binds committed Git corpus bytes, task/profile authority, provider
  qualification, budgets, Delegation, and independent `PASS`/`BLOCK` verification instead of
  accepting caller-minted review claims.
- Generic governed task capabilities and a separate workspace-mutation profile express bounded
  read/write/effect ceilings without making coordination state an integration-time input.
- Durable Attempt awaitables expose bounded observation and wakeup behavior while rejecting
  embedded credentials and unsafe replay states.
- The disposable workspace recovery controller journals exact Attempt-owned roots and supports
  resumable cleanup without granting hidden write or launch authority.
- Provider framing, transport, and bounded-output failures become durable terminal failures rather
  than leaving work indefinitely ambiguous.
- Native Windows gates execute through an exact PowerShell runtime and emit fresh, bounded,
  per-attempt receipts containing cwd, shell/argv identity, duration, exit/failure classification,
  stream hashes, and retained artifact hashes. Missing, stale, unsupported, or changed evidence
  fails closed.
- npm package and release checks invoke the active Node runtime plus the JavaScript npm CLI without
  relying on platform command shims; Windows and POSIX absolute path flavors remain stable on every
  CI host.

## Compatibility and boundaries

- `lexrunner`, `lex-pr`, and `lexrunner-mcp` remain the published binary names.
- Node.js 24 or newer and `@smartergpt/lex@^4.0.0` remain required.
- The stateless integration core still consumes only the frozen plan. Governed WorkItems, Runs,
  Attempts, leases, receipts, reviews, and recovery records remain coordination-time state.
- The release does not claim that a configured persona was applied, that an unbound receipt grants
  merge eligibility, or that a successful command is evidence when its declared artifacts are
  stale or missing.
- Native Windows executable gate parity is additive; existing Linux containment and
  Windows-to-native-WSL projection contracts remain available.

## Release evidence

The exact 1.5.0 release commit must pass lint, typecheck, build, all three full-test shards,
Git-backed tests, Windows bootstrap, frame emission and schema gates, performance smoke, install
script policy, package validation, packed ESM/CommonJS/CLI/MCP smoke, and
`npm run release:publish:check -- --allow-untagged`. The candidate must receive an independent
general review `PASS` and hostile review `PASS` after all release metadata changes.

A signed `lexrunner-v1.5.0` annotated tag may be created only after the exact release-owner-signed
commit is contained in `origin/main`. The stable workflow must verify that both tag and commit are
signed by the authorized release-owner fingerprint, confirm the exact target and main ancestry,
run `npm test`, build, check determinism and version alignment, validate the package and npm dry
run, publish through npm's package-scoped GitHub OIDC trusted publisher, and create the matching
GitHub release. The broader release evidence above remains a prerequisite enforced on the exact
pull-request candidate rather than a claim that every gate is repeated after tagging.

## Publication boundary

This is a release-owner-signed, trusted-workflow npm publication boundary. Agents may prepare,
review, merge, and create the signed tag, but they may not execute a non-dry-run publication from a
local shell. Only the `stable-release` job in `.github/workflows/release.yml` receives publication
authority after exact tag, signer, version, main-ancestry, deterministic-build, package-boundary,
and dry-run checks pass.

If publication fails, inspect and repair the trusted workflow or npm trusted-publisher binding and
rerun that exact failed workflow. Do not publish locally or retarget the immutable release tag.
