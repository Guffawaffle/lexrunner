# LexRunner 2.0.2 generated timeout correction

- Status: **release candidate**
- Prepared: **2026-08-29**
- Supersedes: **2.0.1**

LexRunner 2.0.2 gives generated test and unit gates a realistic, deterministic timeout. GitHub and
multi-repository plan generation now writes an exact five-minute `timeoutMs` into standard `test`
and `unit` gates. Fast and custom gates continue to use the bounded operation fallback, and
multi-repository `unit` gates now use `npm test` plus the standard test artifacts.

## Compatibility

This is a patch release. Hand-authored plans, the 30-second operation fallback, hostility
adjustment, plan schema v1, receipt v2, commands, and MCP tools remain compatible. A plan gate's
exact `timeoutMs` continues to override the hostility-adjusted operation fallback. Generated plan
digests intentionally change because the test timeout is now frozen into the plan's identity.

This release does not change the gate-evidence authority boundary. File-and-hash evidence remains
an unverified observation and cannot grant merge eligibility; issue #865 owns the governed,
plan-pinned verifier work.

## Documentation correction

User-facing runtime documentation no longer advertises `LEX_PR_TIMEOUT` or `gates.yml timeout`
fields that the runner does not consume. Exact gate timeouts belong in frozen plan `timeoutMs`;
CLI and MCP may supply an operation-default timeout only for gates that omit that field.

## Release verification

The exact candidate must preserve timeout identity through the bounded execution result, evidence
manifest, and receipt; pass generator determinism and schema validation; and keep non-test gates
unpinned. It must also pass formatting, typecheck, build, package-boundary validation, packed
consumer smoke, the hosted test matrix, and independent review before signed-tag publication
through npm's package-scoped GitHub OIDC trusted publisher.
